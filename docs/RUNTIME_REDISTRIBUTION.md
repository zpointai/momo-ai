## FFmpeg disposition

Electron's release configuration uses `ffmpeg_branding="Chrome"`, `proprietary_codecs=true`, and a shared FFmpeg component. The exact Windows x64 generated configuration has GPL, nonfree and version-3 options disabled; no x264 or other GPL external library is enabled. Codec support is not itself a GPL license switch. The FFmpeg DLL is unchanged, dynamically imported by the main PE, and not subject to a MoMo replacement lock. LGPL library source accompanies every ZIP, including upstream Chromium changes and Electron's macOS-only patch. This satisfies the chosen source-plus-shared-library distribution route; no promise-only source offer is used. Patent rights are separate from this copyright/notice review.

The huge canonical Chromium notice file includes build/test tools and alternative-license text. For example, the DXC entry explicitly separates GPL Autoconf build/test code from the LLVM runtime grant. A GPL/AGPL/non-commercial word anywhere in that file is not evidence that the running Windows application contains a component under that restriction. The complete canonical notice is preserved rather than shortened based on keyword filtering.

## Microsoft disposition

Physical inventory identifies three Microsoft-origin graphics DLLs. DXC and the post-1.8.2502 DXIL validator use the upstream open-source grants; `d3dcompiler_47.dll` uses Windows SDK distributable terms. The latter remains unmodified, ships only with the classic Windows application, and has its applicable terms supplied prominently in [RUNTIME_NOTICES.md](../RUNTIME_NOTICES.md). Project helper `/MT` builds incorporate release runtime objects; this is distinct from distributing a Microsoft runtime DLL or SDK/compiler library. PE imports show only Windows libraries for the helpers. The SDK redist list expressly permits linked SDK `.lib` results, and Microsoft's licensing guidance describes distribution of linked C++ runtime object code. Toolchain installations used by future distributors must be properly licensed; this package does not redistribute build tools.

The installed product is Visual Studio 2019 Build Tools 16.11.36128.20. Its EULA covers compiler use with Visual Studio editions but does not independently establish the needed runtime distribution grant. The owner answered "Standalone Build Tools only / unsure". General guidance about linked object code is insufficient to resolve that entitlement. The two helper binaries therefore remain blocked; project-owned MIT source is unaffected. Closure requires documented applicable redistribution rights, or a separately authorized rebuild using a toolchain/runtime with an established grant and affected validation. No toolchain was installed or product source changed to bypass this issue.
